# Large-Scale Terrain Data Analysis 2: terrain visibility

Three terrain-visibility applications on the same DEMs, each benchmarked for runtime, memory,
scaling, complexity, rendering and accuracy.

**Final report:** [`report/FINAL_REPORT.md`](report/FINAL_REPORT.md) ([PDF](report/final_report.pdf)) · **Final presentation:** [`presentation/Terrain_Visibility_Final.pdf`](presentation/Terrain_Visibility_Final.pdf)

| Track | Owner | Question | Code |
|---|---|---|---|
| 1 Radar visibility | Person 1 | Which terrain can a stationary radar see? | `radar/` |
| 2 Flight-route visibility | Person 2 | What does an aircraft see along its route? | `flight/` |
| 3 Optimal visibility corridor | Person 3 | Which route minimises radar exposure for its length? | `corridor/` |

Shared conventions (`common/config.py`): Copernicus GLO-30 DSM, Garhwal Himalaya (Uttarakhand),
UTM 44N (EPSG:32644), 30 m cells, nested square DEMs of 500, 1000, 2000 and 4000 cells centred on
Rudraprayag (same resolution, growing coverage); curvature and refraction k = 1/7; heights in metres
above ground; rasters as GeoTIFF, routes as GeoJSON, metrics as CSV, figures as PNG.

See `PLAN_STATUS.md` for what is done and what counts as the 50% mid-submission.

## Running

The DEMs are not in the repository (about 250 MB); `scripts\prepare_data.py` downloads the four
Copernicus tiles and rebuilds them in a few minutes. Intermediate `.npy` arrays and caches are also
regenerated by the scripts. Requires QGIS 3.44 (Windows, OSGeo4W layout under `C:\Program Files\QGIS 3.44.12`).


Everything uses QGIS's Python (it has GDAL, NumPy, SciPy, matplotlib, psutil):

```
run.bat scripts\prepare_data.py          # Phase 0: download DEM tiles, build subsets, synthetic terrains
run.bat -m radar.validate                # Track 1 correctness (synthetic + exact LOS reference)
run.bat -m radar.run_radar               # Track 1 scenario: six radars, coverage maps
run.bat -m radar.benchmark               # Track 1 benchmarks E1-E6  -> results/radar/benchmark_raw.csv
run.bat -m radar.analysis                # Track 1 figures and summary
run.bat -m flight.run_flight             # Track 2 scenario: Alaknanda valley route
run.bat -m flight.benchmark              # Track 2 benchmarks F1-F6
run.bat -m flight.analysis
run.bat -m corridor.run_corridor         # Track 3 scenario: least-exposure routes
run.bat -m corridor.benchmark            # Track 3 benchmarks C1-C5
run.bat -m corridor.analysis
run.bat -m corridor.interactive_bench all  # Track 3 interactive framework: experiments E1-E6 -> results/corridor/interactive/
run.bat -m corridor.extensions_bench all   # Track 3 extensions E7-E15 -> results/corridor/extensions/
run.bat -m corridor.interactive         # Track 3 interactive viewer (click start, right-click goal, drag radars, +/- alpha)
run.bat -m corridor.interactive --demo results\corridor\interactive\demo.gif   # scripted demo, no window
run_qgis.bat qgis\build_project.py       # styled QGIS project + QGIS map renders
run_qgis.bat qgis\render_bench.py        # visualization performance benchmark
python report\build_report.py            # report/mid_submission_report.pdf (system Python + PyMuPDF)
python3 report/build_final_report.py     # report/final_report.pdf from report/FINAL_REPORT.md (headless Chrome)
node presentation\build_pptx.js          # presentation/Terrain_Visibility_Mid_Evaluation.pptx (`npm install` in presentation/ once)
```

`scripts\pipeline.ps1` runs the scenario, benchmark, analysis and QGIS steps one after another
(benchmarks must not overlap, or their timings disturb each other).

Each benchmark run executes in a fresh process (`common/bench.py`). Runs are repeated 5 times
(fewer for the slowest configurations) and medians are reported, while every raw run is kept
in the CSVs. `compute_s` is the algorithm only; `runtime_s` also includes reading the DEM.
Peak memory is the process peak working set (Windows `peak_wset`, Linux `VmHWM`).

### Linux (Ubuntu 22.04, QGIS 3.44, GDAL 3.4)

Use the system Python that ships with QGIS and keep the user site-packages out (a user-installed
NumPy 2.x breaks Ubuntu's GDAL bindings). `OPTICS_RESULTS` sends every output of a run to its own
folder, so results from different machines never overwrite each other:

```
export PYTHONPATH="$PWD" PYTHONNOUSERSITE=1 MPLCONFIGDIR="$PWD/.cache/mpl"
export OPTICS_RESULTS="$PWD/results/linux"      # optional; default is results/
python3 scripts/prepare_data.py                  # or copy data/dem_*.tif and hillshade_*.tif from another clone
python3 -m radar.validate                        # checks the viewshed engine on this GDAL
python3 -m flight.run_flight                     # then flight.benchmark, flight.spacing_study, flight.analysis
```

### Track 2 extensions (branch `track2-extensions`, results in `results/linux/flight/`)

See `flight/TRACK2_EXTENSIONS.md` for what each experiment shows and the numbers; the final deck has five
Track 2 extension slides (built from `results/linux/flight/`), and `integration.pipeline` runs these steps too.

```
python3 -m flight.idea1_bench [F7 F8 F9] --repeats 5   # cheaper computation: shared DEM view, fine-near/coarse-far, tiled memory
python3 -m flight.idea1_analysis                       # figures + F10 complexity model
python3 -m flight.idea2 [sensors timing gsd mc figs]   # sensor model (FOV, resolution, dwell) + Monte Carlo uncertainty
python3 -m flight.usecases [link river sar altitude fleet lookahead figs]   # six applications
QT_QPA_PLATFORM=offscreen python3 qgis/track2_layers.py "$PWD" qgis/track2_extensions.qgz   # QGIS project with playback
QT_QPA_PLATFORM=offscreen python3 qgis/track2_render_bench.py "$PWD"                         # QGIS draw time + playback fps
```

In a running QGIS (Python console): `exec(open("qgis/track2_layers.py").read()); build(QgsProject.instance(), "<repo>")`,
then View > Panels > Temporal Controller and press play.

```
flight/    route.py, visibility.py (baseline/cached/window/parallel/adaptive), run_flight, ...
           fast.py (shared DEM view, multi-resolution, tiled accumulator), sensor.py (FOV / resolution / dwell),
           uncertainty.py (Monte Carlo), usecases.py (link, river, SAR, altitude, fleet, look-ahead),
           idea1_bench.py, idea1_analysis.py, idea2.py, jobs_fast.py, TRACK2_EXTENSIONS.md

           c/gridsearch.c + dstar.inc (compiled searches, cost-to-go field, repair, D* Lite), cgrid.py,
           radarfield.py (per-radar threat updates, detection model), interactive_core.py (Planner),
           interactive.py (viewer), interactive_bench.py; riskcsp.py (certified risk budget), tiles.py
           (tile overlay), altitude.py (3-D routing), placement.py (radar placement game), uncertainty.py,
           alternatives.py, extensions_bench.py; c/: parallel.inc (delta-stepping), csp.inc, tiles.inc, layers.inc
qgis/      build_project.py, render_bench.py, terrain_visibility.qgz,
           track2_layers.py, track2_render_bench.py, track2_extensions.qgz (Track 2 playback project)
data/      DEMs, hillshades, synthetic terrains
results/   radar/, flight/, corridor/, shared/; linux/ (Track 2 runs on the Linux laptop)
report/    mid-submission report
presentation/  PowerPoint deck (15 mid-evaluation slides + backup section) and its generator
```
